# Sequence Diagrams

## 1. Company initiates a payroll run (happy path)

```mermaid
sequenceDiagram
    participant Company
    participant API
    participant Worker as Broadway (payroll-jobs)
    participant Provider as Payment Provider
    participant Webhook as Webhook Handler
    participant Results as Broadway (payment-results)
    participant Invoice as InvoiceWorker (every 1 min)

    %% Company creates the payroll run
    Company->>API: POST /payroll-runs { company_id, pay_period }
    API-->>Company: 202 Accepted { payroll_run_id, status: draft }

    %% Company triggers calculation
    Company->>API: POST /payroll-runs/:id/start
    API->>Worker: Enqueue { job: calculate_payroll, run_id }
    API-->>Company: 202 Accepted

    %% Worker calculates in the background
    Worker->>Worker: Check company balance covers total salaries + fees
    Worker->>Worker: status → calculating
    Worker->>Worker: For each employee: calculate gross, taxes, net → create payroll_intent
    Worker->>Worker: status → pending_approval

    Company->>API: GET /payroll-runs/:id
    API-->>Company: 200 OK { status: pending_approval, total_amount }

    %% Company approves — one message per intent enqueued
    Company->>API: POST /payroll-runs/:id/approve
    API->>Worker: Enqueue { job: execute_payment, intent_id } × N employees
    API-->>Company: 202 Accepted
    Worker->>Worker: status → paying

    %% Broadway processes each intent independently
    par payment per employee
        Worker->>Provider: Send payment instruction { employee, amount, bank_account }
        Provider-->>Worker: 200 Accepted (async — result comes later)
        Worker->>Worker: intent → processing
    end

    %% Provider calls our webhook when each payment settles
    par result per employee
        Provider->>Webhook: POST /webhooks/payment { intent_id, status: success }
        Webhook->>Results: Enqueue { intent_id, status: completed }
        Webhook-->>Provider: 200 OK
        Results->>Results: intent → completed
        Results->>Results: Ledger deduction
        Results->>Results: Generate payslip for this employee
    end

    Invoice->>Invoice: (every 1 min) Find "paying" runs with no intents in pending/processing
    Invoice->>Invoice: Aggregate totals, insert Invoice, run → completed

    Company->>API: GET /payroll-runs/:id
    API-->>Company: 200 OK { status: completed }
```

## 2. Insufficient balance

```mermaid
sequenceDiagram
    participant Company
    participant API
    participant Worker as Broadway (payroll-jobs)

    Company->>API: POST /payroll-runs { company_id, pay_period }
    API-->>Company: 202 Accepted { payroll_run_id, status: draft }

    Company->>API: POST /payroll-runs/:id/start
    API->>Worker: Enqueue { job: calculate_payroll, run_id }
    API-->>Company: 202 Accepted

    Worker->>Worker: Check company balance covers total salaries + fees
    Worker->>Worker: Balance insufficient — status → failed, record error message

    Company->>API: GET /payroll-runs/:id
    API-->>Company: 200 OK { status: failed, error: "insufficient balance" }
```

## 3. Payment failure with retry

```mermaid
sequenceDiagram
    participant Worker as Broadway (payroll-jobs)
    participant Provider as Payment Provider
    participant Webhook as Webhook Handler
    participant Results as Broadway (payment-results)

    %% Picks up from happy path: run is approved, status → paying

    Worker->>Provider: Send payment instruction { employee, amount, bank_account }
    Provider-->>Worker: 200 Accepted
    Worker->>Worker: intent → processing

    Provider->>Webhook: POST /webhooks/payment { intent_id, status: failed }
    Webhook->>Results: Enqueue { intent_id, status: failed }
    Webhook-->>Provider: 200 OK

    Results->>Results: retry_count < 3?

    alt retry
        Results->>Worker: Re-enqueue { job: execute_payment, intent_id }
        Note over Worker,Provider: Retries up to 3 times total
    else max retries reached
        Results->>Results: intent → failed
        Results->>Results: Insert refund transaction into company_transactions
        Results->>Results: Other employees unaffected
    end
```

## 4. Reconciliation (stale processing intent)

Runs every 1 minute inside `InvoiceWorker`. Resolves stuck intents using DB records only —
no provider API call is made. The cutoff for "stuck" is 5 minutes (`updated_at < now() - 5min`).

```mermaid
sequenceDiagram
    participant Worker as InvoiceWorker (every 1 min)
    participant DB

    Worker->>DB: Find intents stuck > 5 min in "processing" or "pending"

    alt processing + PaymentAttempt exists
        Note over Worker: Re-dispatch result from DB record — no provider call needed
        Worker->>DB: Enqueue result (succeeded/failed) based on attempt.status
    else processing + no PaymentAttempt
        Note over Worker: Crash before attempt was recorded
        Worker->>DB: Reset intent → "pending", re-enqueue execute_payment
    else pending + no PaymentAttempt
        Note over Worker: SQS message was lost
        Worker->>DB: Re-enqueue execute_payment
    end
```
